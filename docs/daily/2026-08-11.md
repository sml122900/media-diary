# 2026-08-11 — Phase 13.1: 수식어(커스텀 부문) 시스템

## 배경

별점과 별개로 "어떻게 좋았나"를 유저가 직접 만든 카테고리로 기록하는 기능.
"커스터마이징이 1급 시민"이 원칙 — 생성/이름변경/이모지/삭제/재정렬 전부 마찰 없이.

## 커밋 1 — 스키마 + 백엔드 CRUD (`44367cb`)

`backend/src/app.js`에 `user_epithets`(라벨/이모지/정렬순서, `UNIQUE(user_id, label)`)와
`user_epithet_items`(`user_media.id` 참조 — `tmdb_id` 아님. 2026-08-05 재방문 기록 버그의 교훈)
두 테이블 추가. `backend/src/routes/epithets.js` 신설 — 목록 조회는 LATERAL JOIN +
`json_agg` 단일 쿼리로 N+1 없이 재방문 최대 횟수·시청 연도까지 함께 반환.

curl로 전체 사이클(생성/부착/재정렬/이름변경/중복 409/교차유저 404/CASCADE) 검증,
테스트 계정 삭제로 정리.

## 커밋 2 — DetailModal 부여 UI (`5334ecc`)

`EpithetPicker.jsx` 신설. 부착된 수식어 칩 + "+ 수식어" 버튼 → 피커(탭 토글 부착/해제,
인라인 즉시 생성, 수식어 0~3개일 땐 프리셋 10종 제안). 프리셋 라벨/이모지는 `[카피 초안]`
표시로 남겨 사용자 검수 대상임을 명시.

## 커밋 3 — "나의 수식어" 페이지 (`1b307f6`)

`/epithets` 라우트 + 모바일 메뉴 진입점. 카드 그리드(대표작 큰 포스터, N회 관람 배지) →
상세 화면(Pointer Events 기반 드래그 재정렬 — HTML5 `draggable`은 터치에서 불안정,
새 의존성 추가 대신 선택). 삭제는 기존 `window.confirm()` 패턴 그대로.

브라우저 실사용 검증 중 포스터 `<img>`에 `onError` 폴백이 빠진 것을 발견(깨진 이미지 아이콘
노출) — `MediaCard.jsx`의 기존 패턴대로 추가해 커밋 3에 포함.

## 부수 확인 — rating null/0 일관성
