## 배경

세션 시작 컨텍스트로 매번 읽히는 `CLAUDE.md`가 346줄까지 불어났다.
입력 토큰을 줄이려고 `/caveman-compress`(자연어 파일을 압축하는 스킬)를 돌리는 것으로 시작했으나,

## 1단계 — 문장 압축 (효과 4.8%)

`/caveman-compress CLAUDE.md` 실행.

- 원본 백업: `%LOCALAPPDATA%\caveman-compress\backups\media-diary\CLAUDE.original.md`
- 결과: 22,203자 → 21,133자 (**4.8% 감소**)

효과가 작았던 이유는 파일 구성 때문이다. 압축이 잘 먹히는 영어 산문(코딩 지침)은 전체의 약 15%뿐이고,
나머지는 그대로 보존해야 하는 코드 블록 4개, 바이트 단위로 동일해야 하는 인라인 코드 137개,
그리고 문장 자체가 인과 설명인 한국어 로그 표 2개였다.
로그 표에서 조사·중복 표현을 두 차례 걷어냈지만, 더 줄이면 로그가 존재하는 이유인 진단 내용이 깎이는 지점이었다.

### 검증

스킬의 `validate.py`는 여섯 가지를 검사한다 — 제목 개수/순서, 코드 블록 완전 일치, URL,
경로, 불릿 개수(±15%), 인라인 코드 개수. 전부 통과했다.

```
Valid: True
제목 23개 유지 / 코드 블록 4개 바이트 동일 / 인라인 코드 137개 유지 / 불릿 35 → 35
```

## 2단계 — Python 설치

1단계 당시 이 PC에는 Python이 없었다. `python.exe`/`python3.exe`가 잡히긴 하지만
Microsoft Store 스텁이라 실행하면 스토어 안내만 뜬다. 그래서 압축은 스킬 규칙을 직접 적용하고,
`validate.py`는 Node로 포팅해(`scratchpad/validate.mjs`) 같은 여섯 검사를 돌렸다.

이후 정식 설치:

```bash
winget install --id Python.Python.3.13 --exact --source winget --accept-package-agreements --silent
```

`Python 3.13.14` 설치 확인. 실제 `validate.py`를 돌려 Node 포팅본과 같은 `Valid: True`를 얻었다.
(유일한 차이는 Python `\w`가 한글을 매칭해 "별점/리뷰"를 경로로 오인식한 경고 1건. 오탐이다.)

주의: 설치해도 **실행 중인 셸의 PATH에는 반영되지 않는다.** 2026-07-20 `ANDROID_HOME`,
2026-08-02 `JAVA_HOME`과 같은 현상이다. 새 셸을 열거나 전체 경로를 쓴다.

```
%LOCALAPPDATA%\Programs\Python\Python313\python.exe
```
