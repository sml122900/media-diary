# 2026-08-05 — 실기기 전수 테스트 + 발견 이슈 수정 (통계 레이아웃 / 다크모드 색상 / 토큰 정합성)

## 배경

Play Store 출시(Phase 11) 전 실기기 점검. USB 디버깅으로 연결한
**갤럭시 SM-S942N (Android 16, WebView Chrome 150)** 에서 7개 항목을 테스트했다.

```
□ 로그인 → 작품 목록 (API 통신)
□ ≡ 메뉴 → 우측 슬라이드, 배경 어둡게, 글자 안 잘림, 배경 탭하면 닫힘
□ 작품 추가 검색 "다크나이트"
□ AI 기능 하나
□ 통계 페이지
□ 뒤로가기 (하위→이전, 홈→종료 확인)
□ 이모지 깨짐 있나
```

## 테스트 방법

`adb` + **WebView 원격 디버깅(CDP)** 조합.

- `adb forward tcp:9222 localabstract:webview_devtools_remote_<pid>` 로 WebView에 연결
- Node 22 내장 `WebSocket`으로 CDP 클라이언트를 직접 작성 (`ws` 패키지 불필요)
- `Runtime.evaluate` 로 DOM 측정·한글 입력, `Network.*` 로 API 호출 관찰
- 화면 판정은 `adb exec-out screencap`

`adb shell input text`는 ASCII만 지원해 한글을 못 넣는다. CDP로
네이티브 setter + `input` 이벤트를 발화시켜 React 제어 컴포넌트에 값을 주입했다.

좌표 매핑: CSS 411×801, DPR 2.625, WebView 상단 오프셋 111px
→ `device_x = css_x × 2.625`, `device_y = css_y × 2.625 + 111`

## 수정 1 — 통계 페이지 가로 깨짐 (커밋 `0a037e2`)

`/stats`에서 페이지 폭이 **411 → 850 CSS px** 로 늘어나 도넛·바 차트가 화면 밖으로 잘렸다.

원인 사슬:

1. `ActivityCalendar`가 53주 × (12px 셀 + 3px gap) ≈ **793px의 min-content**를 가짐
2. `.chart-card`는 `.charts-grid`의 **그리드 아이템**인데 `min-width: auto`(기본값)라
   트랙이 793px까지 벌어짐
3. `ResponsiveContainer`가 그 벌어진 폭을 측정해 `.recharts-wrapper`에
   **인라인 `width: 793px`를 고정**
4. 이후엔 고정폭이라 되돌아오지 않음 — 런타임에서 사후에 `min-width:0`을 줘도
   829px에서 멈췄고, `resize` 이벤트로도 재측정되지 않았다

수정: `.chart-card { min-width: 0 }` 한 줄.

검증 (실기기):

```

recharts 컨테이너 793 → 338px
뷰포트 밖 요소    다수 → 0개
캘린더           페이지를 밀어냄 → 내부 스크롤 (보임 338 / 콘텐츠 793)
```

## 수정 2 — 연대별 분포 정렬 오류 (커밋 `0a037e2`)

x축이 `1980s → 1990s → 2000s → 2010s → 2020s → 1970s` 로 1970s가 맨 뒤에 있었다.

```js
Object.entries(counts).sort(([a], [b]) => Number(a) - Number(b))
```

키가 `'1980s'` 문자열이라 `Number('1980s')`가 **NaN**. 비교 함수가 항상 NaN을
반환해 정렬이 사실상 무효화됐다(삽입 순서 유지). 연대 **숫자**를 키로 집계한 뒤
`a.decade - b.decade`로 정렬하도록 수정. 1970s 이전 데이터가 들어와도 안전하다.

## 수정 3 — 다크모드 하드코딩 색상 일괄 정리 (커밋 `060ae76`)

프론트엔드 전체 색상을 스크립트로 감사했다. 다크 카드 배경(#1c1c1c) 대비
명도차를 계산해 위험도를 매기고, 문맥을 전부 확인해 오탐을 걸러냈다.

**실제 문제로 판정해 수정한 것**

- `a { color: #1a1a1a }` — 전역 링크색, 다크 오버라이드 없음 → `inherit`.
  `[data-theme="dark"] a`로 덮으면 특정도 (0,1,1)이 클래스 규칙 (0,1,0)을 이겨
  클래스 지정 색까지 덮어버리므로 `inherit`을 택했다. 라이트 값은 기존과 동일.
- `PIE_COLORS.movie = '#1a1a1a'` — 영화가 85%를 차지해 도넛 대부분이 사라짐 → 테마 분기
- 연대별 바 `fill="#1a1a1a"` → 테마 분기 (dark `#a78bfa`)
- `.feed-username`, FeedPage/PublicProfilePage/ReportsPage 인라인 `#1a1a1a` → 상속
- `.profile-avatar` 다크 배경 추가
- 상태 칩 27곳을 CSS 클래스로 이전 — 인라인 스타일은 CSS 테마를 따라갈 수 없다.
  덤으로 QuickInputModal의 **흰색 모달 배경**, DetailModal 편집 입력창 흰 배경도 해소.

**의도된 것으로 판단해 제외**

- 연말결산(YIR): `background: '#0d1117'` 자체 다크 디자인. `#444`/`#666` 텍스트도
  그 위에서는 의도된 흐린 톤
- 포스터 위 흰 배경 + 진한 글씨 뱃지: 배경·글씨가 한 쌍이라 양 테마에서 동일하게 정상
- `border: #2a2a2a` / `#333` 20여 건: 다크용 테두리. 감사 스크립트가 전경색으로 오판

## 수정 4 — Phase 10 페이지 라이트 모드 미지원 (커밋 `060ae76`)

`/discover`, `/discover/chat`, `/reports/customize`가 **다크 전용으로 하드코딩**돼
있었다 (`.discover-card { background: #1e1e1e }` 등, 라이트 대응 없음).

근본 원인은 색이 아니라 **테마 속성이 아예 설정되지 않은 것**이었다.
`useTheme()`이 페이지별로 호출되는데 이 세 페이지는 호출하지 않아서,
직접 열면 `document.documentElement.dataset.theme`이 `undefined`였다.
그래서 `[data-theme="dark"]` 블록조차 적용된 적이 없고, 결국 값을 다크로
하드코딩해 둔 것으로 보인다.

수정:

- `App.jsx`에서 `useTheme()`을 **루트에서 한 번** 호출 → 어떤 경로로 진입하든 항상 설정
- 기존 다크 정의는 그대로 두고 `[data-theme="light"]` 오버라이드 블록(~50개 규칙) 추가.
  잘 동작 중인 다크를 건드리지 않아 회귀 위험이 없다.

## 수정 5 — 모달에서 뒤로가기가 앱을 종료 (커밋 `0a037e2`)

`useAndroidBackButton`이 경로만 보고 오버레이 상태를 몰랐다.

```js
if (location.pathname !== '/') navigate(-1);
else if (window.confirm('앱을 종료하시겠습니까?')) CapacitorApp.exitApp();
```

작품 추가 모달이 열린 상태에서 뒤로가기 → 모달이 닫히지 않고 종료 확인으로 직행.

프로젝트의 오버레이 11곳이 **모두** 동일 구조라는 점을 이용했다.

```jsx
<div className="backdrop" onClick={e => e.target === e.currentTarget && onClose()}>
```

최상단 백드롭을 `click()` 하는 방식(1파일, ~8줄)으로 처리해
"뒤로가기 = 바깥 탭"으로 의미를 통일했다. 오버레이 스택 등록 방식(11파일 수정)도
검토했으나, 신규 모달이 등록을 빠뜨리면 그대로 앱이 종료되는 반면
백드롭 방식은 같은 패턴만 따르면 자동 커버된다.

검증: 모달·드로어 모두 뒤로가기로 닫히고 앱 유지. `/stats → /`, 홈→종료확인 회귀 없음.

## 수정 7 — 스크린샷 빈 결과 무차감 (커밋 `af041c2`)

인식 결과가 0건이어도 5토큰이 차감됐다. Phase 9 원칙(AI 호출 실패 시 차감 안 함)에 어긋난다.

**환급이 아니라 차감 시점을 뒤로 옮겼다.** `deductTokens`는 fire-and-forget으로
호출되므로, 환급 트랜잭션이 차감보다 먼저 커밋되면 잔액이 오히려 **늘어나는**
레이스가 생긴다. 환급을 넣으려면 `deductTokens`를 `await`로 바꿔야 하는데
그러면 "차감 실패해도 사용자 응답은 정상 반환"이라는 원래 의도가 깨진다.
되돌릴 일을 만들지 않으면 트랜잭션·정합성·환급 남용 문제가 모두 사라진다.

동작 명확화:

- 차감은 **요청당 5토큰** (이미지 장수 무관, 최대 10장)
- `allExtracted`는 전 이미지 병합 결과라 **일부 이미지만 인식돼도 정상 차감**
- **모든 이미지에서 0건일 때만** 무료

기존 피해 이력은 `token_usage_log` 읽기 전용 조회로 확인 — `feature = 'screenshot'`
기록 **0건**이라 보정 대상 없음.

## 테스트 중 겪은 것 (도구/환경)

**삼성 Freecess가 백그라운드 앱을 freeze** — 앱이 백그라운드로 내려가면
`D ActivityManager: freezing <pid> com.mediadiary.app` 이 찍히고 CDP가 응답을
멈춘다. 크래시가 아니라 OS의 절전 동작이었다.

**백그라운드 상태에서 좌표 탭이 다른 앱으로 샜다.** 앱이 포그라운드가 아닌 걸
모르고 `adb shell input tap`을 보내 개인 메신저·Play Store·금융 앱에 입력이
들어갔다. 금융 앱 화면에는 송금 버튼이 있어 위험했다. 이후 **탭 전 포그라운드
검증**을 넣고, 가능한 곳은 CDP 클릭으로 전환했다. 세션 후반에는 사용자 지시로
**좌표 탭을 전면 금지하고 관찰 전용**으로 전환했다.

**JS `confirm()` 다이얼로그가 CDP를 블록한다.** 종료 확인이 뜬 동안
`Runtime.evaluate`가 응답하지 않아 멈춘 것처럼 보였다. `Page.enable` +
`Page.handleJavaScriptDialog`로 해제해야 한다.

**JDK 21 (재확인).** Machine 레벨 `JAVA_HOME`은 Temurin 21로 잘 등록돼 있었으나
실행 중인 셸은 예전 스냅샷(JDK 17)을 들고 있었다(2026-07-20 / 08-02와 동일 현상).
오늘 빌드 6회 모두 명령마다 `$env:JAVA_HOME`을 지정해 우회했다.

**debug keystore 백업이 효과를 봤다.** 08-02에 백업해 둔 `~/.android/debug.keystore`
덕분에 오늘 6회 재설치 전부 `adb install -r`로 처리됐다. 백업이 없었다면
서명 불일치로 매번 `adb uninstall`이 필요했고 로컬 세션·설정이 날아갔을 것이다.
