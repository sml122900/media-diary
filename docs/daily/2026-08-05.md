## 테스트 방법

`adb` + **WebView 원격 디버깅(CDP)** 조합.

- `adb forward tcp:9222 localabstract:webview_devtools_remote_<pid>` 로 WebView에 연결
- Node 22 내장 `WebSocket`으로 CDP 클라이언트를 직접 작성 (`ws` 패키지 불필요)
- `Runtime.evaluate` 로 DOM 측정·한글 입력, `Network.*` 로 API 호출 관찰
- 화면 판정은 `adb exec-out screencap`

`adb shell input text`는 ASCII만 지원해 한글을 못 넣는다. CDP로
네이티브 setter + `input` 이벤트를 발화시켜 React 제어 컴포넌트에 값을 주입했다.

좌표 매핑: CSS 411×801, DPR 2.625, WebView 상단 오프셋 111px
→ `device_x = css_x × 2.625`, `device_y = css_y × 2.625 + 111`

## 수정 2 — 연대별 분포 정렬 오류 (커밋 `0a037e2`)

x축이 `1980s → 1990s → 2000s → 2010s → 2020s → 1970s` 로 1970s가 맨 뒤에 있었다.

```js
Object.entries(counts).sort(([a], [b]) => Number(a) - Number(b))
```

키가 `'1980s'` 문자열이라 `Number('1980s')`가 **NaN**. 비교 함수가 항상 NaN을
반환해 정렬이 사실상 무효화됐다(삽입 순서 유지). 연대 **숫자**를 키로 집계한 뒤
`a.decade - b.decade`로 정렬하도록 수정. 1970s 이전 데이터가 들어와도 안전하다.

## 수정 3 — 다크모드 하드코딩 색상 일괄 정리 (커밋 `060ae76`)

프론트엔드 전체 색상을 스크립트로 감사했다. 다크 카드 배경(#1c1c1c) 대비
명도차를 계산해 위험도를 매기고, 문맥을 전부 확인해 오탐을 걸러냈다.

**실제 문제로 판정해 수정한 것**

- `a { color: #1a1a1a }` — 전역 링크색, 다크 오버라이드 없음 → `inherit`.
  `[data-theme="dark"] a`로 덮으면 특정도 (0,1,1)이 클래스 규칙 (0,1,0)을 이겨
  클래스 지정 색까지 덮어버리므로 `inherit`을 택했다. 라이트 값은 기존과 동일.
- `PIE_COLORS.movie = '#1a1a1a'` — 영화가 85%를 차지해 도넛 대부분이 사라짐 → 테마 분기
- 연대별 바 `fill="#1a1a1a"` → 테마 분기 (dark `#a78bfa`)
- `.feed-username`, FeedPage/PublicProfilePage/ReportsPage 인라인 `#1a1a1a` → 상속
- `.profile-avatar` 다크 배경 추가
- 상태 칩 27곳을 CSS 클래스로 이전 — 인라인 스타일은 CSS 테마를 따라갈 수 없다.
  덤으로 QuickInputModal의 **흰색 모달 배경**, DetailModal 편집 입력창 흰 배경도 해소.

**의도된 것으로 판단해 제외**

- 연말결산(YIR): `background: '#0d1117'` 자체 다크 디자인. `#444`/`#666` 텍스트도
  그 위에서는 의도된 흐린 톤
- 포스터 위 흰 배경 + 진한 글씨 뱃지: 배경·글씨가 한 쌍이라 양 테마에서 동일하게 정상
- `border: #2a2a2a` / `#333` 20여 건: 다크용 테두리. 감사 스크립트가 전경색으로 오판

## 수정 4 — Phase 10 페이지 라이트 모드 미지원 (커밋 `060ae76`)

`/discover`, `/discover/chat`, `/reports/customize`가 **다크 전용으로 하드코딩**돼
있었다 (`.discover-card { background: #1e1e1e }` 등, 라이트 대응 없음).

근본 원인은 색이 아니라 **테마 속성이 아예 설정되지 않은 것**이었다.
`useTheme()`이 페이지별로 호출되는데 이 세 페이지는 호출하지 않아서,
직접 열면 `document.documentElement.dataset.theme`이 `undefined`였다.
그래서 `[data-theme="dark"]` 블록조차 적용된 적이 없고, 결국 값을 다크로
하드코딩해 둔 것으로 보인다.

수정:

- `App.jsx`에서 `useTheme()`을 **루트에서 한 번** 호출 → 어떤 경로로 진입하든 항상 설정
- 기존 다크 정의는 그대로 두고 `[data-theme="light"]` 오버라이드 블록(~50개 규칙) 추가.
  잘 동작 중인 다크를 건드리지 않아 회귀 위험이 없다.

## 수정 5 — 모달에서 뒤로가기가 앱을 종료 (커밋 `0a037e2`)

`useAndroidBackButton`이 경로만 보고 오버레이 상태를 몰랐다.

```js
if (location.pathname !== '/') navigate(-1);
else if (window.confirm('앱을 종료하시겠습니까?')) CapacitorApp.exitApp();
```

작품 추가 모달이 열린 상태에서 뒤로가기 → 모달이 닫히지 않고 종료 확인으로 직행.

프로젝트의 오버레이 11곳이 **모두** 동일 구조라는 점을 이용했다.

```jsx
<div className="backdrop" onClick={e => e.target === e.currentTarget && onClose()}>
```

최상단 백드롭을 `click()` 하는 방식(1파일, ~8줄)으로 처리해
"뒤로가기 = 바깥 탭"으로 의미를 통일했다. 오버레이 스택 등록 방식(11파일 수정)도
검토했으나, 신규 모달이 등록을 빠뜨리면 그대로 앱이 종료되는 반면
백드롭 방식은 같은 패턴만 따르면 자동 커버된다.

검증: 모달·드로어 모두 뒤로가기로 닫히고 앱 유지. `/stats → /`, 홈→종료확인 회귀 없음.

## 테스트 중 겪은 것 (도구/환경)

**삼성 Freecess가 백그라운드 앱을 freeze** — 앱이 백그라운드로 내려가면
`D ActivityManager: freezing <pid> com.mediadiary.app` 이 찍히고 CDP가 응답을
멈춘다. 크래시가 아니라 OS의 절전 동작이었다.

**백그라운드 상태에서 좌표 탭이 다른 앱으로 샜다.** 앱이 포그라운드가 아닌 걸
모르고 `adb shell input tap`을 보내 개인 메신저·Play Store·금융 앱에 입력이
들어갔다. 금융 앱 화면에는 송금 버튼이 있어 위험했다. 이후 **탭 전 포그라운드
검증**을 넣고, 가능한 곳은 CDP 클릭으로 전환했다. 세션 후반에는 사용자 지시로
**좌표 탭을 전면 금지하고 관찰 전용**으로 전환했다.

**JS `confirm()` 다이얼로그가 CDP를 블록한다.** 종료 확인이 뜬 동안
`Runtime.evaluate`가 응답하지 않아 멈춘 것처럼 보였다. `Page.enable` +
`Page.handleJavaScriptDialog`로 해제해야 한다.

**JDK 21 (재확인).** Machine 레벨 `JAVA_HOME`은 Temurin 21로 잘 등록돼 있었으나
실행 중인 셸은 예전 스냅샷(JDK 17)을 들고 있었다(2026-07-20 / 08-02와 동일 현상).
오늘 빌드 6회 모두 명령마다 `$env:JAVA_HOME`을 지정해 우회했다.

**debug keystore 백업이 효과를 봤다.** 08-02에 백업해 둔 `~/.android/debug.keystore`
덕분에 오늘 6회 재설치 전부 `adb install -r`로 처리됐다. 백업이 없었다면
서명 불일치로 매번 `adb uninstall`이 필요했고 로컬 세션·설정이 날아갔을 것이다.

```sh
# 포그라운드 가드 — 우리 앱이 top이 아니면 즉시 실패
TOP=$(adb shell "dumpsys activity activities | grep -m1 topResumedActivity")
case "$TOP" in
  *com.mediadiary.app/.MainActivity*) echo "[FG OK]" ;;
  *) echo "[FG FAIL]"; exit 1 ;;
esac
```

### 검증 중 막혔던 것

- **절전 모드 + 화면 꺼짐 → 앱 네트워크 차단.** 액티비티는 `ResumedActivity`인데
  `dumpsys netpolicy`가 `blocked_state={effective=BATTERY_SAVER|APP_BACKGROUND}`.
  WebView의 모든 외부 요청이 `Failed to fetch`였다. 기기 자체는 LTE 정상(ping 45ms).
  승인받아 `low_power=0`으로 검증하고 종료 시 원복했다.
- **USB 연결이 2회 끊김.** 매번 잠금 해제부터 다시 해야 했다.
- **앱이 로그아웃 상태.** 비밀번호 없이 진행하려고 `JWT_SECRET`으로 본인 계정 토큰을
  발급해 `localStorage`에 주입했다.

## 2. 토큰 정합성 — 4건 연속 수정

### 2-1. `/reports` 헤더 토큰 배지 (`d7f70a5`)

5토큰을 쓰는 화면인데 잔액이 안 보였다. 홈과 동일한 `.token-chip`을 넣고 탭하면 충전 페이지로
보냈다. `/reports/customize`는 이미 `.rc-token`이 있어 변경 없음.

### 2-2. AI 검색 빈 결과 무차감 (`d7f70a5`)

0건은 작품이 없어서가 아니라 TMDB 매칭 실패(이슈 C)로 나는 경우가 있어, **우리 버그로 토큰을
받는** 상태였다. 스크린샷과 동일하게 환급이 아니라 **차감 시점을 결과 확인 뒤로 이동**했다.
실패 쿼리를 `metadata.query`에 남겨 이슈 C 개선 근거로 쓰게 했다.

### 2-3. `customize-chat` 빈 결과 무차감 (`41aac9b`)

AI가 낸 코드를 `REPORT_COMPONENTS`로 거르는데 유효한 게 하나도 안 남으면 사용자는 아무것도 못
받고 2토큰만 나갔다. 검색·스크린샷과 같은 구조라 동일 정책을 적용했다.

프론트에서 별도 버그도 같이 고쳤다 — `setSelected(new Set(codes))`가 무조건 실행돼
**빈 결과가 오면 사용자가 골라둔 항목이 전부 지워졌다.**

### 2-4. 차감 시점을 응답 직전으로 (`2b2e4fd`)

전수 점검 중 발견했다. `deductTokens` 호출 **뒤에도** 실패할 수 있는 작업이 남아 있어, 거기서
터지면 500을 받으면서 토큰만 빠졌다.

| `discover/chat` | `discovery_chats` INSERT ×2 |

## 3. 종료 확인 커스텀 다이얼로그 (`b20afe5`, `4b58979`)

네이티브 `confirm()`은 버튼이 CANCEL/OK 영문 고정이었다. `ExitConfirmDialog`를 신설하고
버튼을 "취소"/"종료"로 바꿨다.

- 훅이 UI를 그리지 않도록 `exitConfirmOpen` 상태와 핸들러를 반환하고 `App`에서 렌더링
- `.exit-overlay`를 `BACKDROP_SELECTOR`에 추가 — 다이얼로그가 열린 상태에서 뒤로가기를 한 번 더
  누르면 종료가 아니라 취소. 프로젝트의 "뒤로가기 = 바깥 탭" 규칙과 동일하게 맞췄다
- `z-index: 10000` (`.rc-confirm` 9999보다 위)

실기기에서 다크/라이트 양쪽을 확인했다. 첫 빌드에서 `autoFocus` 때문에 WebView 기본 주황 포커스
링이 그려져 제거하고 재검증했다.

## 4. 리포트 "다시 생성" 무동작 + 잔액 조회 루트 통합 (`c4eeba8`)

### 4-1. 재생성이 실제로 재생성하지 않았다

`/generate`가 해당 기간 리포트가 있으면 **무조건** `cached: true`로 조기 반환해서, 아래 INSERT의
`ON CONFLICT DO UPDATE`(덮어쓰기)에 영영 도달하지 못했다. UI는 "다시 생성하면 덮어씁니다"라고
안내하는데 실제로는 기존 것을 그대로 돌려주기만 했다. 감상을 더 기록해도 이번 달 리포트를 갱신할
방법이 없던 셈이다. `regenerate` 플래그로 캐시를 건너뛰게 했다.

검증: 내용 해시 `ca3cff57…` → `e71aef62…`, 행 수 1 유지(덮어쓰기), 배지 17 → 12.
캐시 조회는 여전히 0토큰(`cached:true`, `meta` 없음).

### 4-2. 잔액 배지가 직접 진입 시 비어 보임

페이지별로 `fetchBalance`를 부르는 구조라 호출하지 않는 페이지를 직접 열면 `···`로 남았다.
**`useTheme`을 루트로 올렸던 것과 완전히 같은 원인**이라 같은 방식으로 해결했다 — App 루트에서
`token` 변경 시 1회 조회. 표시만 하고 조회 안 하던 3곳(`DiscoverChatPage`, `MemoryChatPage`,
`ReportsCustomizePage`)이 한 번에 해결됐다.

`BillingChargePage`만 개별 호출을 남겼다. 결제 직전 화면이라 다른 기기·탭의 충전 결과를 반영한
최신값이 필요하다.

## 5. 이슈 C — AI 검색 매칭 오류 해결 (`278f84b`, `987c4ec`, `e4a5888`)

세션 1부터 남아 있던 최대 이슈. **진단 → 제안 → 구현** 순으로 진행했다.

### 진단 — 원인이 셋이고, 두 증상의 원인이 서로 달랐다

동일 프롬프트를 직접 호출해 AI 응답을 실측했다.

| 쿼리 | `keywords` 실제 응답 | 판정 |
|---|---|---|
| 우주 배경의 잔잔한 SF 영화 | `Solaris, Stalker, 2001 A Space Odyssey` | 실제 제목 ✅ |
| 90년대 홍콩 느와르 | `Hong Kong noir 1990s` | **장르 설명어** ❌ |
| 크리스토퍼 놀란 SF | `Christopher Nolan` | **인물명** ❌ |

1. **AI 응답에 구조가 없었다.** `keywords` 자유 텍스트라 연도도 원제도 없어 TMDB 결과를 검증할
   기준 자체가 없었다. 프롬프트가 "제목 **또는 핵심 단어**"를 허용해 검색 불가능한 값이 내려왔다.
   **홍콩 느와르 0건은 매칭 실패가 아니라 이것**이었다.
2. **TMDB 매칭 로직이 아예 없었다.** 전체 결과를 `vote_average`로만 정렬했다. TMDB 평점은 표가
   1~4개여도 8점대가 나온다.

   ```
   8.3점 (표     3개)  The Arrival (2017)
   8.0점 (표     1개)  Arrival (2013)
   7.8점 (표     4개)  NXT ArRIVAL (2014)
   7.6점 (표 19,635개) Arrival (2016)  ← 컨택트, 4위로 밀림
   ```

   사용자가 본 결과 3편과 정확히 일치한다. **Arrival 증상은 이것.**
3. **영어 키워드 경로가 `language=en-US`** 여서 제목·줄거리가 영문이었다.

덤으로 회귀 기준으로 삼으려던 "크리스토퍼 놀란 SF"도 이미 깨져 있었다 — TMDB 4건이 전부 놀란에
**관한** 다큐·인터뷰였고 인셉션·인터스텔라는 없었다.

### 수정

- **A.** `tool_choice: any` + `works[{title, original_title, year, tmdb_type}]` required 강제.
  프롬프트에서 "또는 핵심 단어"를 제거했다. 예시로 실제 작품명(Arrival, Parasite)을 들면 AI가 그
  예시를 그대로 답으로 뱉는 회차가 있어 예시도 교체했다.
- **B.** `backend/src/utils/tmdbMatch.js` 신설 — 제목 유사도 + 연도 근접도 + 표수로 점수화하고
  임계 미달은 제외한다. `vote_average` 단독 정렬은 폐기했다.
- **C.** `ko-KR` 통일, `overview`가 비면 원어로 채운다(TMDB는 번역이 없으면 빈 문자열만 준다).
- **D.** 매칭 성공분만 반환하고, 전부 실패하면 기존 빈 결과 무차감 정책이 커버한다.
- `search` / `discover/chat` / `restore/chat` 3개 라우트가 공통 함수를 공유한다.
  `importScreenshot`은 자체 5단계 전략이 이미 동작 중이라 불개입.

### 구현하며 추가로 막은 것 3가지

설계만으로는 부족해 실측을 돌려가며 세 번 보강했다.

1. **원제가 원어인 경우** — 타르코프스키 *Stalker*의 TMDB 원제는 `Сталкер`라 유사도가 무력해진다.
   그 탓에 한국 제목이 우연히 같은 *One Hour Photo*(한국 제목 "스토커")가 이겼다.
   연도를 걸고 검색했는데도 TMDB가 돌려줬다는 사실 자체에 가산점을 줬다.
2. **그 가산점이 쓰레기를 통과시킴** — 제목 유사도 0인 후보가 임계를 넘어 홍콩 느와르 결과에
   *TMNT: Case of the Killer Pizzas*(표 6개), *Gunfire*(1950, 표 2개)가 섞였다.
   제목이 안 닮은 매칭은 "연도 정확 일치 + 표 100개 이상"일 때만 신뢰하도록 제한했다.
3. **부분 문자열 매칭** — `"Snowpiercer"`가 `"Snowpiercer International Special Animation"`에
   포함된다는 이유로 0.85를 받아 표 1개짜리 특별판 애니가 설국열차를 밀어냈다.
   포함 관계 점수를 길이 비율로 스케일했다. 연도도 표도 없는 TMDB 스텁도 제외한다.

## 6. `.gitattributes` — 진단이 틀렸다가 정정된 건

gradle 파일 2개가 계속 `modified`로 떠서 처음엔 줄바꿈(CRLF/LF) 문제로 보고했는데 **틀렸다.**
워크트리 파일 해시가 HEAD blob과 완전히 동일했고(`18894fae…`), 실제 원인은 **git stat 캐시
불일치**였다 — `cap sync`가 매번 같은 내용으로 파일을 다시 써서 mtime만 바뀐 상태였다.
`git add`로 인덱스 stat 정보만 갱신하니 스테이징 없이 깨끗해졌다.

`.gitattributes`는 그래도 넣었다. 경고가 가리키던 재발 경로(git이 CRLF로 체크아웃 → 도구가 LF로
덮어씀 → 진짜 diff 발생)는 실재하기 때문이다.

## 사고 — curl 인코딩으로 잘못된 보고를 한 건

배포 확인용으로 PC에서 `curl -d` 로 한글 쿼리를 보냈더니 AI가 "홍길동"으로 해석해 8건을
반환했다. 이를 "AI 비결정성"이라고 보고했는데 **틀렸다.**

DB에 저장된 쿼리 바이트를 보니 `efbfbd`(U+FFFD 대체 문자)가 반복됐다. Git Bash가 한글을 UTF-8이
아닌 바이트로 curl에 넘겨 **서버 도착 시점에 이미 깨져 있었다.** 기기 WebView에서 보낸 요청은
정상이었다. 이 확인 과정에서 1토큰을 낭비했다.

**교훈**: Windows 셸에서 비ASCII를 외부 명령 인자로 넘길 때는 인코딩을 먼저 의심한다.
관측값이 이상하면 관측 도구부터 검증한다.
