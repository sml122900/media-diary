## 기술 결정

- **캐시 timezone**: `TIMESTAMP` 대신 `EXTRACT(EPOCH FROM (NOW()-col))` 패턴. pg의 TIMESTAMP 파싱이 서버 로컬 TZ 기준이라 UTC 비교 시 오차 발생.
- **위시리스트 API 경로**: `/api/wishlist` → `/api/me/watchlist`. `/api/me/*` 컨텍스트 일관성.
- **재시청 UNIQUE 설계**: `(user_id,title,year)` → `(user_id,title,year,rewatch_count)`. 동일 작품 여러 번 기록 허용하면서 완전한 중복은 방지.

---

## 배운 것

- **pg TIMESTAMP 파싱**: pg 클라이언트는 `TIMESTAMP WITHOUT TIME ZONE` 컬럼을 서버 로컬 TZ로 해석한다. UTC 기반 서비스라면 `TIMESTAMPTZ`를 쓰거나, 시간 비교 자체를 DB에서 처리해야 한다.
- **ON CONFLICT 제약 참조**: `ON CONFLICT (col1, col2)` 구문은 해당 컬럼 조합의 UNIQUE 인덱스 또는 PRIMARY KEY가 반드시 존재해야 한다. 기존 제약을 DROP하면 관련 INSERT 구문도 전부 수정해야 한다.
- **감사 방법론**: 코드만 보고 "구현됨"으로 체크하면 안 된다. 실제 API 호출로 E2E 검증해야 신뢰할 수 있다.
